Pepo is in pilot. You are issued an API key and your base URL together — replace `https://api.joinpepo.com` below with the URL you were given.

<Warning>
**Create your brand profile before anything else.** Every workflow call is refused until one exists — it is what makes results about your brand rather than your category. It is step 2 below, and it is the only step that can block the rest.
</Warning>

## 1. Check your balance

Free, and the fastest way to confirm your key works.

<CodeGroup>
```bash cURL
curl https://api.joinpepo.com/v1/credits \
  -H "Authorization: Bearer $PEPO_API_KEY"
```

```ts TypeScript
const res = await fetch('https://api.joinpepo.com/v1/credits', {
  headers: { Authorization: `Bearer ${process.env.PEPO_API_KEY}` },
})
console.log(await res.json())
```

```python Python
import os, requests

r = requests.get(
    "https://api.joinpepo.com/v1/credits",
    headers={"Authorization": f"Bearer {os.environ['PEPO_API_KEY']}"},
)
print(r.json())
```
</CodeGroup>

```json Response
{ "balance_usd": 20.0, "default_call_cap_usd": null, "mode": "live" }
```

## 2. Create your brand profile

Every workflow reads it, and it's what makes results about *your* brand rather than your category. A new workspace returns `"status": "needs_setup"` until you create one.

```bash
curl -X POST https://api.joinpepo.com/v1/brand-profile \
  -H "Authorization: Bearer $PEPO_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "brand_names": ["KISS", "KISS Nails"],
    "competitors": ["Glamnetics", "Static Nails"],
    "category": "press-on nails",
    "exclusions": ["recall"]
  }'
```

```json Response
{ "status": "approved", "version": 1, "profile": { ... } }
```

`brand_names` is the only required field — include spelling variants, since consumers rarely write your brand the way your style guide does. Everything else sharpens the results and can be added later. `exclusions` is worth filling in now: it's enforced on every result, so topics you never want surfaced are withheld before they reach you.

<Tip>
Prefer not to write JSON? The `pepo-setup-brand` prompt in [Claude](/mcp/overview) researches your brand and drafts the whole profile for you to approve. Same result.
</Tip>

Full field list: [Brand profile](/brand-profile).

## 3. Price the call before you make it

Cost tracks how many posts the call reads, which Pepo can count exactly — so the estimate matches the invoice.

```bash
curl -X POST https://api.joinpepo.com/v1/estimate \
  -H "Authorization: Bearer $PEPO_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{"endpoint":"/v1/trending","params":{"limit":25,"platforms":["tiktok"]}}'
```

```json Response
{
  "estimate": {
    "cost_usd": { "low": 0.83, "expected": 0.83, "high": 0.83 },
    "assumes": { "posts_considered": 412, "videos_returned": 25, "platforms": 1 },
    "balance_usd": 20.0,
    "affordable": true
  }
}
```

`posts_considered` is what drives the price — how many posts in your corpus match the filters, not how many results you asked for. Narrowing `window` or `platforms` reads fewer posts and costs less; asking for 10 results instead of 25 doesn't change it.

## 4. Ask what is trending

```bash
curl -X POST https://api.joinpepo.com/v1/trending \
  -H "Authorization: Bearer $PEPO_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{"platforms":["tiktok"],"window":"7d","limit":10,"max_cost_usd":5}'
```

`max_cost_usd` is a hard ceiling. Work stops there and returns partial results marked `usage.truncated` rather than overrunning it.

## 5. Read the result properly

This is the part worth slowing down for. A trimmed real response:

```json
{
  "results": [
    {
      "video": { "creator": { "handle": "@breakout" }, "url": "https://tiktok.com/…" },
      "metrics": { "views": 240000 },
      "momentum": {
        "score": 87,
        "classification": "trending",
        "confidence": "medium",
        "coverage": { "snapshots": 3, "hours_observed": 24 },
        "comparison_group": { "n": 27 },
        "floors_met": true,
        "gated_by": null
      }
    },
    {
      "video": { "creator": { "handle": "@thin" } },
      "metrics": { "views": 800000 },
      "momentum": {
        "score": 87,
        "classification": "watchlist",
        "confidence": "low",
        "coverage": { "snapshots": 2, "hours_observed": 3 },
        "floors_met": false,
        "gated_by": "Capped at watchlist: 2 snapshot(s) over 3h — \"trending\" requires at least 3 across 12h."
      }
    }
  ],
  "trend": {
    "verdict": "viral_video",
    "independent_creators": 1,
    "top_creator_share": 0.766,
    "reasons": ["A single video/creator dominates. One video outperforming is virality, not a trend."]
  },
  "caveat": null,
  "usage": { "cost_usd": 0.83, "balance_usd": 19.17 }
}
```

Three things to take from it:

<Steps>
  <Step title="The biggest number is not the answer">
    `@thin` has more than three times the views and is the one held at `watchlist`, because three hours of observation cannot show a trajectory. `gated_by` says so in words you can quote.
  </Step>
  <Step title="Check `floors_met` before you repeat a claim">
    It is the single field that says whether the evidence bar was cleared. `classification` plus `floors_met` is the honest summary; `score` on its own is not.
  </Step>
  <Step title="`trend` is a separate finding from `results`">
    Here five accelerating videos come from one creator holding 77% of the views, so the verdict is `viral_video`, not a trend. Ranking and movement are different questions.
  </Step>
</Steps>

<Warning>
If `caveat` is non-null, it is the most important field in the response. It says when the corpus cannot support the question you asked — no metric history yet, an empty corpus, or too little history to classify anything. Pass it on rather than summarising around it.
</Warning>
